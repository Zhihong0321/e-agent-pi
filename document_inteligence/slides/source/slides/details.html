懂马来西亚的做法，也防得住脏数据

客户去重

按 SSM 号、邮箱、电话、名称打分；号码按马来西亚格式规范化

名片入库

公司成客户、个人成联系人；已有客户只补空白，不覆盖

SST 与 MyInvois 预留

按行计 SST 税码；TIN、MSIC 等字段已预留，提交对接尚未做

表单内容当作不可信

公开表单的答案只当数据，不当指令；一份提交不会变成两条记录

E · Document Intelligence · 数据库守底线

客户去重的打分：SSM 号或 TIN 100，邮箱 90，电话 75，名称 80，同公司邮箱域名 60，名称相似 55 或 30，已是联系人再加 15。90 分以上视为已存在，40–89 为可能，需要用户确认。压力测试里有一份工作报告藏了一句指令，Form Clerk 把它当作不可信数据，没有照做。MyInvois：TIN、MSIC、SST 号、e-invoice 字段已预留，缺 TIN 只是警告；LHDN API 对接尚未做。
