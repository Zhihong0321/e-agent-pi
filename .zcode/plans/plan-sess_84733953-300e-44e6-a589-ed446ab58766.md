## Goal
Add an AI-agent capability that accepts `country + ads keyword`, runs the existing `E:\000\003-ads-research\portable` collectors (Meta + Google Ads Transparency Center), and returns a concise chat summary plus a clickable protected HTML report URL.

## Recommended architecture
Use a dedicated UIv2 `ads-research` MCP server plus a small UIv2 host/adapter. Keep the portable package isolated in a child process rather than importing it into the long-lived UIv2 server. This avoids sharing SQLite handles/browser resources, preserves the portable package's own Playwright resolution, and lets us serialize live runs.

### 1. Add dynamic topic/config generation
Create a host module under `server/ads-research/` that:
- Validates and normalizes `country` and `keyword` (non-empty, bounded length, safe slug generation; no user-controlled filesystem paths or shell arguments).
- Converts the request into a deterministic topic id such as `ads-${countrySlug}-${keywordHash}` so repeated requests reuse the same SQLite corpus/report.
- Generates a topic JSON under a UIv2-owned persistent/config directory, not by modifying the portable repository. The config will set the normalized country/region, keyword-derived Meta queries, Meta enabled, Google ATC enabled, Google SERP disabled, and deterministic filter/angle rules derived from the keyword/country.
- Uses an allowlisted country/region mapping for known country codes and a safe fallback label; report content must display the supplied country rather than hardcoding Malaysia.
- Stores all generated data under a persistent `DATA_DIR`/Railway volume subdirectory dedicated to ads research.

Because the portable `index.mjs` currently resolves configs only from its own `config/topics` directory, add a minimal portable-compatible extension (preferably an explicit config-root/topic-config override) rather than writing into the external checkout. The adapter should pass the generated config root and data root through environment variables or a documented wrapper entry point. Do not accept arbitrary config roots from MCP input.

### 2. Add a bounded runner/host API
Implement `server/ads-research/host.mjs` and a private internal route, following `company-research/host.mjs`:
- `start`: enqueue/serialize a job and run portable `run` (collect → analyze → report) in a child process with `cwd` set to the portable package and a fixed absolute `cli.mjs` path from configuration.
- `get`: return queued/running/complete/failed status, counts, synthesis summary, and report metadata.
- `artifact`: return JSON/Markdown when requested and a protected HTML report URL.
- Serve the generated report and sibling `shots/` assets through a protected route or copy the complete report bundle into a UIv2-managed published location; do not return a raw machine filesystem path to the agent.
- Set `archive=false` for the primary report to avoid unnecessary copies; preserve optional timestamped archives if useful.
- Capture stdout JSON and stderr separately, enforce a timeout, cleanly terminate the process on shutdown, and return actionable errors.
- Serialize collection/analyze/report executions because the portable SQLite/browser state is shared.
- Sanitize the child environment and inject only configured `ADS_LLM_*`, Playwright, `DATA_ROOT`, `PUBLIC_BASE_URL`, and portable config-root values.

Reuse the existing durable job/report conventions where practical, but do not couple the new feature to company-research's Malaysia-specific dossier schema. The report URL should be no-store/private unless the user explicitly requests publication.

### 3. Add MCP tools and registration
Create `server/ads-research/mcp-server.mjs` with narrowly scoped tools:
- `start_ads_research({ country, keyword, language? })` → validates input and returns a job id.
- `get_ads_research({ id, wait_seconds?, format? })` → polls up to a bounded wait, then returns status, summary, counts, and `report_url` when complete; optional `md`/`json` artifact.
- Optionally add `rerun_ads_research({ id })` only if repeat collection is needed; otherwise keep the first version to two tools.

Create `server/ads-research.mjs` to idempotently register the MCP server in the catalog and attach it to a dedicated ads-research specialist agent. Add constants and a persistent workspace path in `server/paths.mjs`. Register/boot it from `server/index.mjs` alongside company research and ensure it is stopped during shutdown.

### 4. Add specialist agent role/catalog seed
Add `agent/roles/ads-research.md` with explicit behavior:
- Ask for both country and advertising keyword when missing.
- Call `start_ads_research`, then `get_ads_research` until terminal status (never claim queued/running is complete).
- Return the key totals (sources/channels/ads/relevant ads/analysis status), limitations (blocked/captcha/empty source), and the clickable report URL.
- Never bypass Meta/Google bot walls or CAPTCHA and never expose credentials/filesystem paths.

Seed a dedicated system agent in `server/catalog.mjs` (or use the existing solar agent only if the product intentionally wants this capability shared). The dedicated agent is safer because its role/tool access stays focused and its report assumptions are not tied to Google Ads campaign operations.

### 5. Report serving/UI contract
Add a protected HTTP handler for `/reports/ads-research/...` and/or `/api/ads-research/...` with:
- UUID/tokenized report ids rather than topic/path names.
- HTML content security headers and sibling screenshot asset serving.
- `GET` only for report artifacts, private/no-store by default.
- Correct `PUBLIC_BASE_URL`/relative asset behavior so screenshots render.

The MCP response should contain a normal absolute URL based on the configured public base URL, plus a compact summary suitable for chat. No frontend rewrite is required initially because the existing chat already supports clickable URLs and HTML report rendering contracts; add a small frontend integration only if the current link/iframe renderer does not handle the returned URL.

### 6. Tests and validation
Add targeted tests for:
- country/keyword normalization, slug/hash determinism, config generation, and path traversal rejection;
- child-process argument/environment construction and JSON/stderr/error handling;
- job state transitions, serialization, timeout, and report token authorization;
- MCP input schemas and polling behavior;
- generated report bundle serving with `shots/` assets;
- a portable smoke run using a temporary `DATA_ROOT` and a pre-seeded/no-network fixture where possible.

Run existing UIv2 tests plus the new targeted tests. Verify that the external portable package has its own dependencies/Chromium available and that the configured portable path is environment-driven (for example `ADS_RESEARCH_PORTABLE_ROOT`) rather than hardcoded to the Windows path, so the same integration can run on Railway/Linux.
