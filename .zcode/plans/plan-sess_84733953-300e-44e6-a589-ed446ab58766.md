## Production fix

### 1. Vendor the portable runtime into UIv2
Copy only the portable package's executable source into a repository-owned directory such as `server/ads-research/portable/`:
- `cli.mjs`, `index.mjs`
- `src/**`
- `config/topics/**` templates
- `package.json` and `package-lock.json`

Exclude local/generated state:
- `data/**`
- `out/**`
- `node_modules/**`
- screenshots, SQLite databases, archives and local credentials

This makes the production Docker build self-contained instead of depending on a Windows path outside the repository.

### 2. Install portable dependencies in Docker
Update `Dockerfile` after the main dependency install to run `npm ci --omit=dev` in the vendored portable package with browser download disabled. Reuse the image's existing Chromium installation through `PLAYWRIGHT_BROWSERS_PATH=/opt/playwright`.

The portable package must retain its own `node_modules` because its `playwright` import resolves from the portable package ancestry.

### 3. Make host path resolution production-safe
Update `server/ads-research/host.mjs` so `ADS_RESEARCH_PORTABLE_ROOT` is optional and defaults to the vendored production path under `server/ads-research/portable`, while still allowing a local override for development.

Keep all generated state under the existing persistent `DATA_DIR`:
- `/storage/ads-research/config`
- `/storage/ads-research/runtime`
- `/storage/ads-research/jobs`

Do not write to the repository checkout at runtime.

### 4. Make production report URLs explicit
Use `ADS_RESEARCH_PUBLIC_URL` when configured; otherwise derive the URL from `RAILWAY_PUBLIC_DOMAIN`. Return a URL such as:

`https://<production-domain>/reports/ads-research/<job-id>/report.html`

Keep reports and screenshot assets behind the authenticated application route. The MCP response should never expose `/storage` paths.

### 5. Configure required production secrets
Document/add deployment configuration for:
- `ADS_LLM_BASE_URL`
- `ADS_LLM_MODEL`
- `ADS_LLM_KEY`
- optional `ADS_RESEARCH_PUBLIC_URL`
- optional `ADS_RESEARCH_ATC_DOMAINS` and `ADS_RESEARCH_ATC_ADVERTISERS`

The production agent must have LLM credentials for the analyze/synthesis stage. If they are absent, the job should fail clearly after collection rather than claim a completed analyzed report.

Do not commit the supplied admin username/password or any model key. Those credentials are only for the production UI login if needed.

### 6. Add production-focused tests
Extend Ads Research tests to verify:
- default portable root points to the vendored directory;
- a Railway-style `/storage` data root is used for generated state;
- report URL uses `RAILWAY_PUBLIC_DOMAIN`/`ADS_RESEARCH_PUBLIC_URL`;
- no local Windows path is required;
- generated report and `shots/` assets remain outside the repository checkout.

Run:
- `npm run test:ads-research`
- `npm run build`
- syntax/lint checks
- a production-mode smoke test using the vendored CLI and temporary storage

### 7. Commit and deploy
Commit only the production Ads Research packaging/runtime changes on `main`, preserving unrelated working-tree modifications. Push `main` to `origin` so Railway can build the self-contained image. After deployment, run the real `Malaysia + ev charger` job through the production agent and return its actual protected report URL.
