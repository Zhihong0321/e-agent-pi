## Phase 2 — Correct effects, replay, and authorization (P0)
Target modules: `server/execution/dispatch.mjs`, `store.mjs`, `registry.mjs`, `routes.mjs`, client submission handling, migrations, and concurrent DB tests.

1. Reserve/serialize `(attempt, callId, operation/version, argument digest)` atomically before invoking a mutating operation. Make same-key/different-operation or different-argument reuse a conflict. Replays return the stored winner without rerunning the effect.
2. Keep local business mutation, effect receipt, successful tool result, and event in one transaction; prevent the current post-effect journal race. Ensure rollback leaves no success receipt or successful result.

4. Recheck current identity, membership, role/profile authorization, manifest revision, generation/lease ownership, cancellation and confirmation at the host boundary and before terminal writes. Reject forged receipts/artifacts and stale-owner writes.

Keep PGlite/fake-worker tests as regression coverage but do not present them as production boundary proof.
